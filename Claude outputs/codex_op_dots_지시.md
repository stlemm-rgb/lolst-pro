## 사용자 요청 (원문 요약)

### ① 사기 챔피언
- 시즌 중에 **패치 실수**로 메타에서 지나치게 좋은 챔피언(SS랭크, SSS랭크 수준)이 **가끔** 나오면 좋겠다.
- SSS 챔피언은 나왔다가 **글로벌 밴**(리그 모든 경기에서 사실상 밴/사용 금지)을 당하는 일도 있고,
- 의도와 반대로 너무 강해서 **게임사가 사과하는 인터뷰**나 SNS·기사로도 나오면 좋겠다.

지금 코드(Claude가 확인한 것): 메타 = js/champions.js makePatch(year, week, prefer) → state.meta { champs[pos], s[pos], s2[pos] }, 등급 metaTier는 S/A 두 가지, 효과 MATCH.metaPickBonus·metaPowerBonus[tier] (data/match.js), 밴 = banValue·matchPower(bans), 상대가 내 챔피언을 밴 MATCH.bansAgainstMe·banWeights. 대격변 = js/shakeup.js·data/era.js. NPC 숙련 js/npc_mastery.js (npcPatchNews). 패치 주기는 nextWeek의 '새 챔피언·패치'. 메타 표시 metaTagHTML(.meta-tag.tier-S/A).

조사·설계해 줄 것:
1. 지금 패치가 언제·얼마나 자주 바뀌는지, S급이 경기 승률에 주는 실제 효과 크기(코드상 숫자), 내 선수·NPC·밴 계산에 등급이 어디에 쓰이는지 표.
2. SS·SSS를 넣는 **설계 후보 2~3개** (예: 가 = 등급만 추가해 기존 보너스 표에 SS·SSS 값 / 나 = '사고 패치' 사건으로 몇 주 지속 → 핫픽스(다음 패치 하향) → 글로벌 밴 단계 / 다 = …). 각 후보마다: 얼마나 자주(시즌당 확률), 몇 주 지속, 효과 크기, 내 선수에게 의미(그 챔피언 숙련도가 높으면 기회, 없으면 위기 — 고를 거리), NPC 반응(숙련·픽·밴), 글로벌 밴 규칙(밴 칸을 하나 쓰는지·아예 못 고르는지), 끝나는 방법(핫픽스 너프·리워크).
3. 뉴스·SNS·인터뷰: 어떤 순간에 무엇이 나오나(발견 → 커뮤니티 난리 → 프로 경기 픽률 → 게임사 사과 인터뷰 → 핫픽스/글로벌 밴), 기존 어느 함수·데이터 파일에 붙일지(publishHeadline·SNS 글 data/social_posts*.js·받은 연락 data/events*.js), 글 예시 몇 줄(조사 규칙 지킬 것, 실제 게임사·실명 대신 게임 속 이름이 있으면 그것).
4. **정답지(golden) 영향**: 게임 결과가 바뀌는 설계면 정답지 새로 만들기가 필요 → 확률을 뽑을 때 게임 난수를 쓰면 다른 모든 결과가 밀림. 예전 세이브(state.meta에 새 칸) 처리.
5. 위험: 밸런스(내 선수가 SSS 하나로 너무 쉬워짐), 실제 LoL 역사 진행(② 실제 역사에 맞춘 진행, 2027년 이후 가짜 역사 금지)과 충돌하는지.

### ② 미니맵 선수 움직임 (js/replay.js rpDotHome·drawReplayDots, data/replay.js REPLAY_DOTS·REPLAY_SHOW.phase, css .rp-dot)
사용자: "선수들의 움직임이 지나치게 부자연스러움. 라인에만 붙어 있다가 갑자기 한 번에 모였다가 한 번에 흩어진다. 경기가 끝난 상태에서도 패배·승리와 상관없이 라인에만 붙어 있음."

Claude가 본 원인 후보: 시간대(phase) 경계에서 평소 자리가 한순간에 바뀜 / 장면 앞뒤 near(0.9분, 1배속 약 1초) 동안 선형으로 끌려갔다 돌아옴 → 10명이 동시에 모였다 흩어짐 / 정글이 3분마다 두 캠프를 순간이동 / 좌표를 매 프레임 left·top으로 바로 넣고 이동 속도 제한·보간이 없음(.rp-dot에 transition이 있는지 확인) / 세트 끝(t ≥ box.min) 처리 없음.

조사·설계해 줄 것:
1. 위 원인이 맞는지 코드로 확인 + 빠진 원인.
2. 자연스럽게 만드는 안 2~3개 (예: 가 = 프레임마다 목표 좌표로 최대 속도만큼만 다가감(정해진 시간만 쓰는 순수 함수로 — 되감기·세트 클릭·하이라이트 점프에서도 같은 자리가 나와야 함, 상태를 쌓는 방식이면 점프할 때 처리) / 나 = 장면 관련 선수만 일찍 출발(모이는 시간 앞쪽 길게·흩어지는 시간 뒤쪽 길게), 무관한 선수는 라인·정글 동선(캠프 사이를 걸어감)·귀환·백도어 / 다 = 라인 따라 미니언 웨이브처럼 앞뒤로 움직임(라인 경로 위 비율 좌표)). 각 안의 장단점, 휴대폰 성능, motionOff(움직임 끄기) 때 처리.
3. 경기 끝: 이긴 팀은 상대 넥서스로 몰려가고 진 팀은 본진 쪽 흐려짐/쓰러짐 등 — 어떤 모양이 좋은지 후보, 경기 기록(s.w, box.min) 어디서 승패를 아는지.
4. **연출 무작위는 fxRandom/rpJit 같은 자리 기반만** — 게임 난수(Math.random·게임 rand) 금지, 정답지 그대로여야 함.

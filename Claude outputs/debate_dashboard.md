## 1라운드: Codex 의견 (Opus 의견을 보지 않고)

제 추천은 **“이번 주 행동을 보여 주는 작은 방 + 결정에 필요한 정보만 남긴 대시보드 + 연락과 선수 SNS를 함께 보는 휴대폰”**입니다. 방을 기존 화면에 추가만 하면 모바일이 더 길어집니다. 방이 차지하는 만큼 기존 설명과 중복 정보를 덜어내야 합니다.

아래는 상대 의견을 보지 않은 독립적인 1라운드 제안입니다. 첨부 이미지·사실표와 관련 코드를 확인했으며 파일은 수정하지 않았습니다. 수치는 구현 후 검증할 목표입니다.

**1. 이번 주 행동 그림**

**[추천안] 128×96 원본, 작은 선수 한 명, 동일한 방의 세 가지 장면**

| 항목 | 제안 |
|---|---|
| 방 원본 | **128×96px**, 바닥 선은 가로 2칸·세로 1칸의 아이소메트릭 |
| 표시 크기 | PC·390px 모바일 모두 **2배인 256×192px**. 넓은 시안에서만 3배인 384×288px 비교 |
| 선수 크기 | 서 있을 때 **8×14px**, 머리 6×5px. 화면에서는 16×28px |
| 색 | 방 공통 12~16색 + 기존 피부색·머리색·팀 유니폼 주색/보조색 |
| 구성 | 방 바탕 1개 + 장면별 소품 묶음 3개 + 선수 자세 3개 |
| 배치 | PC는 이번 주 행동 카드 왼쪽, 모바일은 주차·휴대폰 버튼 바로 아래 |

참고 그림의 침대·창문·포스터·쿠션은 유지하되, 장식은 **주요 소품 5~7개**로 제한합니다. 기존 네온 UI 안에 밝은 방이 너무 튀지 않도록 벽은 회보라, 바닥은 청록 계열의 낮은 채도로 조정합니다.

- **훈련:** 책상·모니터·키보드·의자. 선수는 옆모습으로 앉고, 모니터 내용만 훈련 종류에 맞춰 바꿉니다. 리플레이 분석은 타임라인, 챔피언 연습은 단순한 표적 모양입니다.
- **휴식:** 침대·쿠션·컵. 선수는 기대거나 눕습니다. 잠든 모습은 눈을 계속 감고, 깜박임은 앉아 쉬는 자세에서만 적용합니다.
- **경기:** 같은 방에 팀색 재킷·가방을 두고 선수가 경기 준비를 합니다. **‘경기 준비 · 이번 주 2경기’**라고 써서 방 안에서 공식 경기를 치르는 것으로 오해하지 않게 합니다.

경기가 있는 주에도 훈련은 진행될 수 있으므로 그림 아래에는 항상 **‘리플레이 분석 · 경기 2’**처럼 두 정보를 함께 표시합니다. 장면은 경기 준비를 우선하되, 훈련 내용이 사라지면 안 됩니다.

**움직임은 4개의 합성 상태면 충분합니다.** 숨쉬기 2상태 × 눈 열림/감김 2상태입니다. 발·의자는 고정하고 어깨와 상체 윤곽만 원본 1px 바꿉니다. 숨쉬기는 약 3.2초 주기, 눈 감김은 120ms, 다음 깜박임 간격은 `fxRandom()`으로 3~6초를 정합니다. 전체 몸을 위아래로 옮기면 숨쉬기보다 점프로 보입니다.

매번 방 전체를 그리지 말고 정적 바탕과 선수 상태를 캐시합니다. 타이머 하나로 다음 상태 전환 때만 다시 그리며, 화면 밖·다른 메뉴·백그라운드에서는 중지합니다. 기존 움직임 끄기 설정과 `prefers-reduced-motion` 모두에서 정지 프레임을 사용합니다. 60fps 반복 렌더링은 필요 없습니다.

작은 선수를 ‘내 선수’로 느끼게 하는 핵심은 얼굴 디테일보다 **같은 색과 같은 자리의 연속성**입니다. 기존 외형의 피부·머리색과 팀색을 그대로 가져오고, 방 밖에 이름·팀을 표시합니다. 이적하면 유니폼만 자연스럽게 바뀝니다. 클릭하면 기존 선수 정보로 연결하고, 새 방 꾸미기 능력치나 소유 아이템은 만들지 않습니다.

**[대안]**

1. **144×108px, 2배 288×216px:** 참고 그림의 가구 표현에 유리합니다. 대신 모바일 첫 화면에서 24px를 더 소비합니다.
2. 경기 장면만 별도의 아이소메트릭 경기 부스로 구성합니다. 행동 구분은 더 명확하지만, 같은 생활 공간이라는 애착과 제작 효율이 줄어듭니다.

**[위험·반대 근거]**

- 사람을 크게 만들면 방보다 초상화가 중심이 됩니다. 먼저 8×14px로 확인하고 최대 10×16px까지만 비교하는 편이 좋습니다.
- 작은 머리에서는 깜박임이 거의 안 보일 수 있습니다. 눈을 키우기보다 2배 화면에서 실제로 보이는지 확인해야 합니다.
- 현재 휴식 버튼은 `advanceWeek(true)`를 **즉시 실행**합니다. 방을 위해 ‘휴식 선택 → 확인’ 단계를 추가하면 기존 조작이 바뀝니다. 휴식 장면은 기존 진행 직후 짧게 보여 주되 ‘지난주 휴식’으로 명시하고, 연출을 기다려야 진행되는 구조는 피합니다.
- 거주 형태와 다른 고급 방을 그리면 소유한 집으로 오해할 수 있습니다. 실제 주거를 재현할지, 행동을 나타내는 공통 무대로 삼을지 시안에서 확인해야 합니다.

본문 15px, 줄간격 1.5 정도, 카드 높이 약 **140~190px**로 잡습니다. 390×900에서 완전한 글 3~4개를 보는 것이 목표입니다. 한 화면에 많은 글을 넣기보다 작성자와 글 사이에 충분한 공간을 줘야 지금의 게시판 목록에서 벗어납니다. 사진은 기존 글에 이미지 데이터가 없으므로 첫 버전에서 제외합니다.

**화면용 반응 수는 저장하지 않고 고정 키에서 계산합니다.** 예를 들어 `연도|주차|메시지 id|작성자`를 기존 `pfSeed()`로 해시하고 범위에 매핑합니다. 팬 글 0~49, 선수 글 20~499 정도를 시안용 범위로 제안합니다. 이는 난수 생성 호출이 아닌 고정 계산이라 새로 열어도 숫자가 바뀌지 않습니다. `Math.random()`이나 게임의 `pick()`·`randInt()`를 쓰지 않습니다. 실제 난수가 필요한 연출만 `fxRandom()`을 사용합니다.

## 1. 이번 주 행동 그림

4초 반복을 출발점으로 삼되 화면 밖에서는 정지하고, 움직임 끄기에서는 정지 프레임을 사용합니다. JS 타이머가 없다고 렌더링 비용까지 없는 것은 아닙니다.

둘 다 **한 페이지 + 접기**, 390×900 기준 기본 상태 약 2화면이라는 같은 방향입니다.  
합의 수치는 **1,400~1,700px 권장, 1,800px 상한**으로 두고, 펼친 상세·팝업은 별도 측정하면 됩니다.  
길이보다 우선할 조건은 첫 화면에서 행동·새 연락·상태를 파악하고, 고정 진행 버튼이 콘텐츠를 가리지 않는 것입니다.

**합의안 요약 10줄**

1. 방은 96×64 ×3, 사람은 색만 구분되는 작은 크기로 시작한다.
2. CSS 프레임 띠를 쓰되 몸 전체 대신 상체 윤곽만 움직인다.
3. 휴식 방은 실제 거주 중인 집과 합숙 상태를 반영한다.
4. 대시보드는 이번 주 계획, 요약 창은 지난주 실제 행동을 보여 준다.
5. 경기 주에는 경기장 부스의 준비 장면과 훈련명을 함께 표시한다.
6. 휴대폰 진입은 최신 연락 배너로 만들고 연락·언급 수를 구분한다.
7. 일반 설명은 접고 현재 결정에 필요한 규칙 경고는 남긴다.
8. 역할별 글자 규칙·약칭을 적용하고 390px에서 잘림과 개행을 검사한다.
9. SNS는 실제 글과 연결된 얼굴 줄·프로필·알림·하트를 넣고 반복 글은 접는다.
10. 모바일은 한 페이지와 접기로 구성하고 기본 길이를 2화면 이내로 맞춘다.

**여전히 사용자에게 물어야 할 선택지**

- **픽셀 질감:** **96×64 ×3의 굵은 도트(추천)** / 128×96 ×2의 섬세한 도트. 같은 표시 높이의 시안으로 비교할 선택입니다.

- **SNS 얼굴 줄:** **이번 주 작성자 줄, 누르면 글로 이동(추천)** / 얼굴 줄 없이 피드부터.
- **SNS 반응:** **고정된 연출용 하트 수(추천)** / 반응 숫자 없음 / 실제 댓글 기능까지 확장.

### Codex 반대·위험 (모두 최종안에 반영)

1. **장면 분기에 훈련 미선택 상태가 빠짐.** `state.plan`이 없으면 실제로 주 진행을 막는데, 초안은 훈련 방으로 표시함. ‘훈련 선택 필요’ 상태를 따로 둬야 함. (`js/main.js:658`)

2. **‘답장 대기 없음’을 ‘새 연락 없음’으로 표시하면 오정보.** 현재 연락 수에는 답장 선택지가 없는 미읽음 메시지도 포함됨. 답장 대기가 없으면 최신 미읽음 연락으로 대체해야 함. (`js/events.js:606`)

### ① 이번 주 행동 그림
- 방 96×64 논리 픽셀을 정수 3배(288×192)로 표시. 사람은 앉은 키 9px·선 키 12px, 머리 3×3(머리색·피부색), 몸은 유니폼 2색. 눈은 피부를 가리면 1점이나 생략.
- 움직임: 프레임 20장 가로 띠를 한 번 그려 캐시 → CSS steps(20) 4초 반복(JS 타이머 0, 무작위 0). 숨쉬기 = 발·엉덩이·의자 고정, 어깨·머리만 1px. 깜박임 4초에 1번. 화면 밖·다른 메뉴에선 멈춤, 움직임 끄기·prefers-reduced-motion은 정지 그림.

- 그림 아래 한 줄: '31주차 · 🏋️ 리플레이 분석 · 경기 2'.
- 요약 창의 '지난주 장면'은 주 진행 때 실제 훈련·집·경기 정보를 weekReport에 따로 기록해서 그림 (지금 상태로 거꾸로 추측하지 않음).
- 코드: data/room.js(소품·색·자세) + js/room.js(그리기·캐시). 색은 portrait.js의 PORTRAIT·uniformOfTeam 재사용.

### ② 대시보드
- PC와 모바일 따로 그림 (760px 기준, 보이는 쪽만 만듦).
- 모바일 순서: 행동 그림 → 📱 알림 배너 → 이번 주 경기 한 줄 카드(누르면 펼침, 조합 전략 변경도 여기) → 상태 2×2(체력·컨디션·종합 능력·돈) → 퀘스트 1개 → [더 보기]. 숙련도·솔랭·스탯·최근 경기는 다른 메뉴로. 기본 길이 1,400~1,700px(약 2화면, 지금 6.2화면).
- PC 첫 화면: 왼쪽 [행동 그림 + 이번 주 할 일 + 경기 요약], 오른쪽 [📱 휴대폰 위젯 + 상태 4칸]. 그 아래 지난주 결과·퀘스트·챔피언.
- 설명 기준: 늘 보이는 규칙 설명·용어 풀이는 모바일에서 숨김. 지금 내 선택에 영향을 주는 경고(예: 체력 30 미만이면 경기력 감소)는 그 상황에서만 한 줄.
- 📱 알림 배너: 답장 대기 최신 연락 1개(보낸 사람·제목·미리보기). 답장 대기가 없으면 안 읽은 최신 연락. 둘 다 없을 때만 '새 연락 없음'. 숫자는 '연락 3 · 언급 2'로 나눔. 모바일 아래 탭 SNS → 📱 휴대폰.
- 긴 글자: 칸 역할별 규칙(숫자·단위·짧은 버튼 = 한 줄 / 이름 = 한 줄 말줄임 + 눌러서 전체 / 연락 제목 = 2줄까지 / 설명 = 줄바꿈 허용 / 모바일 훈련 표 = 세로 목록) + data의 짧은 이름(팀 약칭·스탯 짧은 이름) + tools/에 390px 검사(한 줄 설계 칸의 개행·잘림·겹침 0).

### ③ 휴대폰 안 선수 SNS
- 휴대폰 아래 앱 바: 💬 메시지 / 📸 SNS(게임 속 가짜 앱 이름) / 🔔 알림(나를 언급).
- SNS: 이번 주 글쓴이 얼굴 줄(누르면 그 글로) · 글 카드(얼굴·이름·✔프로·팀·'2주 전'·본문 4줄+더 보기·❤ 숫자) · 최근 12개 + 이전 글 · 같은 본문은 '같은 내용의 글 n개 보기'로 접기(안 읽은 언급 제외) · 내 프로필(작은 사람·팬 n명·팀). 댓글 숫자는 넣지 않음(댓글 기능이 없으므로).
- ❤ 숫자: 글 id 해시 + 글쓴이 인기로 계산, 저장 안 함, 게임 결과 영향 0, 다시 열어도 같음.
- 읽음: 화면에 실제로 보인 글만 읽음 + '모두 읽음' 버튼 (지금은 SNS 탭만 열어도 전부 읽음).
- SNS 메뉴의 선수 SNS 탭도 같은 카드 함수를 씀.

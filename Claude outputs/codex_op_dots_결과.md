아래에서 **현재 수치**는 코드 확인 결과이고, **제안 수치**는 구현 후 밸런스 측정이 필요한 초안입니다. 실제 LoL 사건을 재현하는 설계는 이번 범위에 넣지 않았습니다.

S의 **경기력 +15%는 승률 +15%p가 아닙니다.** 스탯 점수 70, 숙련도 80, 다른 보너스와 메타 불이익을 제외하면 다음과 같습니다.

| 등급 | 계산 결과 |
|---|---:|
| 비메타 | 77.00 |
| A | 83.16 |
| S | 88.55 |

S는 A보다 이 부분의 경기력이 약 6.5% 높습니다. 라인전·팀 조합·사건까지 연결되므로 최종 승률 변화는 별도 경기 반복 측정이 필요합니다. `data/match.js` 상단 설명의 **S +8%·A +3%는 낡은 주석**입니다.

추천 수치에서 SSS는 S보다 해당 경기력 배율이 약 14.8% 높습니다. 하지만 다른 조건을 제외해도 좋은 사건 가중치는 약 **1.51배**가 됩니다. 처음부터 +50% 같은 값을 넣는 것은 피하는 편이 좋습니다.

또한 숙련도 20의 SSS 경기력은 위 조건에서 약 78.23으로, 숙련도 80의 S인 88.55보다 낮습니다. **숙련도 없이도 무조건 강한 챔피언이 되지 않는 방향**입니다.

추천안의 구체적인 규칙은 다음과 같습니다.

- 사건은 시즌 중 경기 일정이 있는 주에 시작하고, **다음 정기 패치 전까지 종료할 수 있는 주만** 후보로 둡니다.
- 한 번에 챔피언 한 명, 지정 포지션 하나를 SS 또는 SSS로 올립니다. 출시 전 챔피언은 제외합니다.
- NPC는 기존 주 2회 연습 중 메타를 선택한 경우 사고 챔피언을 우선합니다. 연습 횟수나 숙련도 상승량 자체는 늘리지 않습니다.
- SS·SSS의 메타 평균 비중은 우선 S와 같은 2로 둡니다. 등급이 높다고 적응 불이익까지 크게 증폭시키지 않습니다.
- **글로벌 밴은 일반 밴 칸을 쓰지 않는 사용 금지**로 처리합니다. 국내·해외·국제대회 및 예외 픽 경로 모두 같은 제한을 사용합니다.
- 사용 금지 중에는 경기용 메타 불이익 계산에서도 제외합니다. 수동 연습은 허용하되 자동 연습은 대체 챔피언을 추천합니다.
- 종료 시 사고 보너스만 제거합니다. 기본 S/A 등급과 기존 숙련도는 유지합니다. 리워크·숙련도 초기화는 첫 구현에서 제외합니다.

현재 게임은 선수별 견제 밴을 계산하는 구조입니다. 실제 LoL처럼 팀 전체 밴 순서를 정확하게 재현하는 구조가 아니므로, 글로벌 밴을 일반 밴 한 칸으로 끼워 넣으면 규칙이 불명확해집니다.

> “{champ}은(는) 이번 주부터 대회에서 사용할 수 없다. 일반 밴 횟수에는 포함되지 않는다.”

픽률·승률은 실제 저장된 경기에서 계산한 수치만 쓰고, 표본이 없으면 수치 기사를 생략합니다. `{champ}은(는)`처럼 프로젝트 조사 규칙도 적용합니다.

사건 추첨은 경기 규칙이므로 `fxRandom()`을 쓰면 안 됩니다. 화면 효과 난수와 별개로 **저장되는 전용 사건 씨앗**을 두는 방식을 권합니다. 기존 저장의 최초 씨앗은 저장된 값으로 결정적으로 만들고, 이후에는 사건 전용 난수만 사용합니다. 그러면 추첨 자체가 기존 게임 난수를 추가 소비하지 않습니다. 다만 사건이 실제 경기를 바꾸면서 이후 결과가 달라지는 것은 정상입니다.

역사 진행과는 분리해야 합니다. 이 사건을 실제 연도별 역사 기사에 넣거나 실제 회사의 발언으로 꾸미지 않습니다. **현재 규칙의 “2027년 이후 가짜 역사 금지”를 고려하면, 첫 구현은 2026년까지로 제한**하는 편을 권합니다. 이후 연도에도 가상 시즌 사건을 허용할지는 역사 진행 정책과 함께 정하면 됩니다.

| 경기 종료 배치 없음 | 도트 함수에는 없음. 재생 종료 처리는 있지만 도트는 평소 위치 계산을 그대로 사용 |
| 사망·복귀 순간이동 | 추가 원인. 사망 즉시 본진, 0.8분 후 평소 위치로 즉시 복귀 |
| 겹치는 사건에서 튐 | 추가 원인. 더 강한 사건을 찾을 때 이미 바뀐 좌표에 다시 섞으므로 사건 순서의 영향이 생김 |
| 움직임 끄기 | 현재는 작은 흔들림만 끔. 집결·위치 전환은 계속 발생 |

첫 세트의 기본 위치 함수에서 경계 직전과 직후를 비교한 최대 이동량입니다. 맵 좌표는 가로·세로 각각 0~100입니다.

| 경계 | 순간 이동 거리 |
|---|---:|
| 3분 | 약 21.2 |
| 14분 | 약 51.1 |
| 26분 | 약 25.3 |

실제 사건이나 사망 표시가 덮이면 화면에서 보이는 값은 달라지지만, **기본 위치 자체에 큰 불연속이 있다는 점은 확인됐습니다.**

| 후보 | 무엇이 보이나 | 장점 | 단점·위험 | 정답지 바뀜? |
|---|---|---|---|---|
| 가. 목표 좌표까지 속도 제한 | 기존 움직임이 천천히 따라감 | 변경 범위가 작음 | 집결 방식은 그대로. 프레임별 누적 방식이면 되감기·배속에 따라 위치가 달라짐 | 아니요 |
| **나. 선수별 시간표·이동 경로 — 추천** | 관련 선수만 미리 이동, 정글은 캠프 사이를 걸음, 사망 후 복귀 | 원인을 함께 해결. 같은 시각의 위치가 항상 같음 | 경로 충돌·장면 우선순위 설계 필요 | 아니요 |
| 다. 라인 경로에서 앞뒤 이동 | 라인전이 살아 움직이는 느낌 | 가볍고 구현하기 쉬움 | 한타 집결·사망·종료 문제는 별도로 남음 | 아니요 |

추천은 **나를 중심으로, 평소 라인 움직임에 다를 조금 섞는 방식**입니다.

세트마다 선수 10명의 시간표를 한 번 만들고, 재생할 때는 해당 시각의 위치만 읽습니다.

```js
const RP_PATHS = new WeakMap();

function rpBuildDotPaths(set, setIndex) {

  // 사망·부활·복귀 구간
  // 경기 종료 배치
}

function rpDotAt(paths, side, laneIndex, t) {

}
```

핵심 규칙은 다음과 같습니다.

- **실제 경과 프레임이 아니라 경기 시각 `t`로 계산**합니다. 1배속·3배속·되감기·하이라이트 점프에서 같은 위치가 나옵니다.
- 경로를 잇는 구간은 반드시 같은 끝점을 공유합니다. 부드러운 보간을 써도 경로 끝점이 다르면 튀는 문제가 남습니다.
- 초기 목표 이동 속도는 맵 좌표 기준 경기 1분당 최대 25 정도로 시험합니다. 먼 선수는 먼저 출발하고, 가까운 선수는 늦게 출발합니다.
- 작은 교전은 주인공·피해자 중심, 오브젝트는 정글·서포트와 주변 선수, 큰 한타는 다수 참여로 구분합니다.
- 사건 간격이 너무 짧으면 가장 가까운 중요 사건을 우선하고, 모든 선수가 모든 장면에 도착하도록 억지로 이동시키지 않습니다.
- 정글은 두 캠프 사이 경유점을 따라 움직입니다. 탑·원딜·미드는 라인 경로를 따라 소폭 전진·후퇴합니다.
- 사망 시 그 자리에서 흐려진 뒤 숨김 → 본진에서 복귀 → 경로를 따라 이동합니다. 사망 순간 본진까지 날아가는 모습은 없앱니다.
- 초반 버전에서는 실제 기록이 없는 귀환·백도어를 무작정 만들지 않고, 해당 사건이 있을 때 연결합니다.

현재 경기에는 실제 이동 기록이 없습니다. 따라서 이 경로는 경기 기록에 맞춘 화면 연출이며, 경기 결과 객체에 새 이동 기록을 붙이지 않고 `WeakMap`에만 보관하는 것이 좋습니다.

무작위 위치 차이는 `rpJit(세트·선수·사건으로 만든 고정값)`처럼 결정적으로 계산합니다. `fxRandom()`도 게임 난수와는 분리되어 있지만 호출 순서에 따라 값이 달라지므로, **되감기 가능한 이동 경로에는 `rpJit` 방식이 더 적합**합니다.

휴대폰에서는 경로를 매 프레임 다시 만들지 않고, 좌표 계산 10개와 표시 갱신만 합니다. 처음에는 초당 30회 갱신으로 확인하고, `transform` 이동을 사용한다면 좌표 기준이 맵 크기인지 확인해야 합니다. CSS의 `translate(%)`는 기본적으로 도트 자신의 크기를 기준으로 하기 때문입니다.

`motionOff()`에서는 흔들림·연속 이동·서서히 흐려짐을 끄고, **장면별 정적인 위치와 종료 배치만 즉시 표시**하는 방식을 권합니다.

**경기 끝 모양**

승패는 이미 `s.w`에 있습니다. `0`이면 `m.a`, `1`이면 `m.b` 승리입니다. 종료 시각은 `s.box.min`입니다.

| 후보 | 모습 | 판단 |
|---|---|---|
| **승리 팀은 상대 본진 주변, 패배 팀은 본진 방어 위치에서 흐려짐** | 승패를 바로 이해할 수 있음 | 추천 |
| 패배 팀 전원 쓰러짐 | 강한 종료 연출 | 실제로 전멸한 기록이 없어도 전멸처럼 보여 비추천 |

종료 직전 약 2~3분의 경로를 자연스럽게 연결하고, `t >= box.min`이면 최종 배치를 고정합니다. 승리 팀도 전원이 넥서스 한 점에 겹치지 않게 펼칩니다. 사망 중인 선수는 숨김을 유지하고, 마지막 사건에 백도어가 명시된 경우에는 해당 선수 중심 배치를 우선합니다.
